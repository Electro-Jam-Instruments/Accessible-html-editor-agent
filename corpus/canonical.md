# Canonical scenario set — one row per scenario, three editors per row

**Status: converged merge, 2026-08.** Built from the three source inventories, not from new research:
[open-notebook.md](inventories/open-notebook.md) (83 rows), [lexical.md](inventories/lexical.md) (201 rows) and
[ckeditor5.md](inventories/ckeditor5.md) (302 rows) — **586 input rows, collapsed to 218 canonical scenarios**.

A canonical scenario is **one thing a user did**, described the way the user would describe it
("I typed a hyphen and got a bullet"), with a column per editor showing how that editor
implements it and how it fails to convey it. Rows are collapsed on **user intent**, never on
implementation detail: `- ` + space is one scenario with three implementations, not three
scenarios.

Vocabulary is the vocabulary of the framework docs: the seven patterns and the priority ranking
from [synthesis.md](../docs/synthesis.md); the eight entry / eight exit vectors from
[containment-state-machine.md](../contract/containment.md); the invariants this set must
instantiate from [conformance-suite-design.md](../contract/invariants.md); and the
buckets, the state-vs-transition distinction and the structural-vs-transition failure classes
from [layered-gap-analysis.md](../docs/the-gap.md).

---

## What this corpus does not cover

Three editors are inventoried: Open Notebook's markdown editor, Lexical and CKEditor 5.
By weekly npm downloads that is roughly 0, 5.0M and 1.3M — while the two most-deployed
families are absent entirely: **ProseMirror/Tiptap (~19M combined)** and **Quill (8.0M,
dormant since 2024-11)**. The omission is history, not judgement: we inventoried what was
in front of us. It is being closed (a Tiptap/StarterKit inventory is in progress; Quill
is planned as measure-only), and until it is, the corpus characterises *these three
editors*, not "editing surfaces on the web". Figures and sourcing:
[editor-landscape.md](../docs/editor-landscape.md).

## How to read a row

| Column | Meaning |
|---|---|
| `canonicalId` | `CAN-<bucket>-<nnn>`. Stable; cite these from the conformance suite. |
| `bucket` | `B1` automated conversion · `B2` user-initiated state · `B3` menus · `CB` container boundary. |
| `title` | The operation, as a user would name it. |
| `userIntent` | What the user was trying to do. Two rows are the same scenario if this sentence is the same. |
| `needsToKnow` | The semantic tokens that must reach the user at the moment it happens — the input to the conformance suite's vocabulary module. Terse and reused across rows on purpose. |
| `container` / `vector` | CB rows only: which container type, and which of the 8 entry / 8 exit vectors. |
| `failureClass` | `structural` (the result carries no semantics — no announcement can repair it) · `transition` (the result is fine, the user was not told) · `both` · `none` (no failure; usually a row that must correctly announce nothing, or a positive control). |
| `gapType` | `standards` — ARIA cannot express it, so even a perfect implementation must synthesise a string · `implementation` — the pattern exists and is simply not followed. |
| `priority` | `P1`/`P2`/`P3`, derived below. |
| `*Source` | The row id(s) in that editor's inventory. |
| `*Status` | What reaches the user today. |

### The status vocabulary, and the one distinction that must not be blurred

| Value | Means |
|---|---|
| `announced` | The information reaches the user **at the moment of the change** — by a live region, by the platform reading real semantics, or by CKEditor's fake-selection trick. Which mechanism is named in the notes; `PLATFORM` marks the ones the browser and AT do without the editor's help. |
| `silent` | The editor implements the operation and conveys nothing. |
| `structural-fail` | The result carries **no real semantics regardless of announcement** — Open Notebook's markdown textarea producing a literal `- ` with no list, Lexical's `CollapsibleContainerNode` rendering `<div open="">`, CKEditor's unlabelled table widget announcing a non-breaking space. Nothing to navigate, review, or repair with a message. |
| `n/a` | **The editor does not implement this at all.** Not a failure. |

**`n/a` is not `silent`, and conflating them would invert the whole comparison.** An editor with no
blockquote scores `n/a` on blockquote rows; an editor that ships blockquote and says nothing scores
`silent`. Without that split, the most minimal editor in the survey would appear to be the best
one. This is the single most important correctness property of this merge, and it is why the
coverage table below excludes `n/a` rows from each editor's denominator.

A source cell of **`—`** means something different again: *the editor supports the operation, and
its inventory has no distinct row for it* (usually because the inventory covered it generically).
The status is still given. `—` cells cite nothing and so contribute nothing to the reconciliation.

### How priority was derived

From [synthesis.md](../docs/synthesis.md)'s ranking (1: B1 + container entry/exit · 2: B2 state
disclosure · 3: B3 menus · 4: structural, editor-specific), modulated by the frequency recorded in
the source inventories:

- **P1** — rank-1 class at medium-to-high frequency, plus the two B2 rows synthesis calls the
  hardest and most novel (the collapsed-caret pending style and its untoggle), plus the
  containment-stack row that P1 of the synthesis is about.
- **P2** — rank-1 at low frequency, the rest of B2 state disclosure, and the four typeahead rows
  that carry invariants M-2 to M-5.
- **P3** — everything else: low-frequency operations, presentational features with no accessible
  expression, mouse-only affordances, premium/`INFERRED` rows, and recorded absences.

## Coverage summary

Counts are of **canonical scenarios**, not of source rows. "Reaches the user" is
`announced ÷ (rows where that editor is not n/a)` — **the denominator deliberately excludes `n/a`**,
so an editor is measured only on what it actually implements. Measuring against all 218 rows instead
would reward an editor for not having features, which is exactly the inversion this merge exists to
prevent.

Two footnotes on those numbers, both of which make them slightly *kinder* than they look:

1. **12 canonical rows carry `failureClass: none`** — rows that must correctly announce nothing
   (invariant C-2: Enter inside a code block, moving between two to-do items), and positive
   controls where an editor does the right thing (CKEditor's `aria-hidden` minimap, everyone's
   modal dialogs). Their `silent` entries are not failures and are still counted as not reaching
   the user.
2. **`announced` is generous.** It credits the platform as well as the editor. Where a screen
   reader reports a list or a table cell entirely on its own, from markup the editor merely
   emitted correctly, this table scores `announced` and the row's note says `PLATFORM`. Score
   only editor-originated announcements and every figure below falls further.

The shape of the result matches the source inventories and sharpens them: **CKEditor is the best
performer and still conveys nothing in the large majority of what it implements; Lexical's
announcements are four well-built extensions attached to a corpus of ~200; Open Notebook's failures
are disproportionately `structural-fail` rather than `silent`, which is a different and worse
class — its editing surface is a `<textarea>`, so most of its rows have nothing to announce
*about*.**

### Why these percentages differ from the source inventories' headline figures

The inventories score **their own rows**; this table scores **canonical scenarios**, and the two
differ for three stated reasons. None of them is a correction to the source documents.

- **Collapse reweights.** CKEditor enumerated 302 rows and Lexical 201 for largely the same product
  surface, so a per-source-row percentage is partly a measure of how finely each agent chose to
  slice. One row per scenario removes that.
- **Platform-carried rows are credited consistently.** The Lexical inventory scores arrow-entry into
  a list as not announced (it counts 0 of 70 CB rows); the CKEditor inventory credits the identical
  mechanism — real `<ul>`/`<li>` read by the AT — as reaching the user. Both are right about their
  own bookkeeping and they cannot both stand in one table, so this merge scores **by mechanism**:
  same structure, same score. That is the main reason Lexical reads 11% here against the ~5% its own
  document reports, and it is a judgement call worth knowing about.
- **Deployment is not modelled.** Lexical's figure is for the playground on the extension API. Every
  one of its announcers is an opt-in extension, and the legacy `@lexical/react` plugin path that
  most deployed applications use pulls in **none** of them. As deployed, Lexical's column is closer
  to zero than to 11%.

## Canonical examples — six rows that explain the whole problem

Chosen for how well they explain the finding to someone who has not read the inventories.

### CAN-CB-036 — `- ` + space becomes a bulleted list

| | Open Notebook | Lexical | CKEditor 5 |
|---|---|---|---|
| status | **structural-fail** | **silent** | **silent** |
| rows | — | LEX-B1-003, LEX-CB-030 | CKE-B1-001, CKE-B1-002, CKE-BC-038 |

The whole problem in one keystroke, and it separates the two failure classes cleanly. Lexical and CKEditor both produce a real `<ul><li>` and say nothing — a **transition** failure on correct structure. Open Notebook produces the two literal characters `- ` and no list at any layer — a **structural** failure, where no announcement could help because there is nothing to navigate afterwards. It is also the highest-frequency autoformat that exists, and the announcer pattern that would fix it ships twice over in Lexical's own repository, for headings and auto-links.

### CAN-B2-002 — Ctrl+B with a collapsed caret

| | Open Notebook | Lexical | CKEditor 5 |
|---|---|---|---|
| status | **n/a** | **silent** | **silent** |
| rows | — | LEX-B2-002 | CKE-B2-002 |

The hardest gap, and the one that explains why this is a standards problem rather than a bug list. The state concerns text that does not yet exist: there is no element, attribute or accessibility-tree object anywhere to hang it on. Both rich editors compute it correctly and spend it on a CSS class or an unfocused button. And Open Notebook is `n/a` here, not `silent` — the case does not arise, because it expands the caret to the surrounding word and mutates it immediately. Two editors fail because ARIA cannot describe a future; the third fails because the concept is absent. A suite that only tested announcements would score them identically.

### CAN-CB-018 — A fence of three backticks becomes a code block — and CKEditor announces it

| | Open Notebook | Lexical | CKEditor 5 |
|---|---|---|---|
| status | **n/a** | **structural-fail** | **announced** |
| rows | n/a — not supported | LEX-B1-008, LEX-CB-018 | CKE-B1-014, CKE-BC-022 |

The existence proof, and the reason the ask to maintainers is not 'do a large amount of work'. CKEditor announces *every* entry and exit vector for the code block — autoformat, toolbar, arrow in from above or below, Backspace merging you in, undo relocating you in, Enter out, arrow out, toggle out — from twelve lines hooked on `selection.on('change:range')` that diff `focus.parent`. That listener is entirely container-agnostic. Blockquote and lists sit silent in the same repository next to working code that would fix them.

### CAN-CB-003 — Arrow down into a blockquote

| | Open Notebook | Lexical | CKEditor 5 |
|---|---|---|---|
| status | **n/a** | **silent** | **silent** |
| rows | n/a — not supported | LEX-CB-003 | CKE-BC-003, CKE-BC-010 |

Why 'the editor announces blockquote' is not a sufficient answer. A container has many independent entry vectors implemented in different code paths, and they fail independently (invariant C-3). An editor that announces autoformat entry and nothing on arrow entry has taught the user to trust a signal that is not reliable — which is worse than silence, because they now believe they are outside the quote when they are inside it. **CORRECTED 2026-08:** this passage claimed the platform rescues nobody here. NVDA reports blockquote by default (see [platform-rescue.md](../docs/platform-rescue.md)), so the failure is narrower than stated: the user is not told *when it happens*, but does find out on navigation.

### CAN-CB-046 — Enter on an empty list item

| | Open Notebook | Lexical | CKEditor 5 |
|---|---|---|---|
| status | **structural-fail** | **silent** | **silent** |
| rows | ON-B1-006 | LEX-CB-036 | CKE-B2-025, CKE-BC-047 |

The clearest evidence that a standard is needed, because the three editors disagree — and one of them disagrees with itself. Lexical's blockquote exits on **any** Enter; its code block needs **two** blank lines; its list needs **one** empty item; and a *nested* list item drops a level instead of leaving. CKEditor's list has the same nested/top-level split. Open Notebook has no exit branch at all, so the list is unbounded and the canonical escape hatch does not exist. A user cannot learn this by exploration, and what they learn in one editor is wrong in the next.

### CAN-B3-002 — Typing to filter a typeahead menu

| | Open Notebook | Lexical | CKEditor 5 |
|---|---|---|---|
| status | **silent** | **structural-fail** | **structural-fail** |
| rows | ON-B3-006 | LEX-B3-002 | CKE-B3-003 |

The implementation gap, stated at its most concrete. The combobox pattern is completely specified and nobody follows it. Lexical's option ids are positional and each keystroke calls `setHighlightedIndex(0)` rather than `updateSelectedIndex(0)` — so `aria-activedescendant` does not change at all while the user types, even though the option it names is a different option after every keystroke. CKEditor's entire mention package contains zero `aria` or `role` references. No menu in any editor exposes a result count. This one needs conformance tests and bug reports, not a proposal.

## Divergence index — where the three editors disagree on the same operation

23 canonical scenarios carry an explicit `divergence` note. These are the strongest evidence
for a standard, because they show the failure is not effort or capability: three teams solved
the same user-visible operation three incompatible ways and told nobody. They are listed here
so they are easy to find; each is repeated in full on its own row.

| [CAN-CB-070](#can-cb-070) | Arrowing past the table's outer edge | Lexical's handlers move the caret to a paragraph outside the table (platform-readable). CKEditor selects the table widget instead of exiting, and that widget is unlabelled (CAN-CB-065). |

| [CAN-B1-017](#can-b1-017) | Quotes, dashes and ellipses are silently retypographed | two of the three editors do not implement typographic substitution at all — that is n/a, not a pass. Open Notebook's textarea additionally sets spellCheck=false, so the AT cannot report misspellings either. |
| [CAN-B2-002](#can-b2-002) | Ctrl+B with a collapsed caret — a pending style with no anchor | the case does not exist in Open Notebook at all — selectWord expands the caret to the surrounding word and mutates it immediately (CAN-B1-025). | [CAN-B2-009](#can-b2-009) | A command sets the heading level | Lexical announces 'Heading level N' and 'Heading level N removed' — and announces NOTHING when leaving a quote, list or code block by the same command. CKEditor is silent but exposes the current value on the dropdown's label. |
| [CAN-B2-023](#can-b2-023) | Undo and redo | Lexical announces the constant strings 'Undone' / 'Redone', which name nothing. CKEditor announces nothing and ALSO restores the selection ranges, so the user is moved as well as having content changed. |

| [CAN-B2-038](#can-b2-038) | The editor's mode changes | Lexical announces 'Editor is read-only' / 'Editor is editable' (transition-based, so the initial mount is silent). | [CAN-B2-048](#can-b2-048) | The keyboard route into and out of the toolbar | Lexical and CKEditor both implement Alt+F10 plus a roving tabindex, collapsing the toolbar to one tab stop and restoring the prior selection on return. | [CAN-B3-001](#can-b3-001) | A caret-anchored menu opens | Open Notebook has no caret-anchored menu at all; its command palette is a cmdk combobox in a dialog and is the one surface in the app where role, name and option count are computed correctly by the browser. | [CAN-B3-014](#can-b3-014) | A toolbar dropdown opens | CKEditor wires aria-haspopup and aria-expanded on every dropdown button; neither Lexical's DropDown nor Open Notebook's toolbar group sets either, and neither panel carries role='menu' or role='listbox'. Open Notebook's dropdown is a display:none/block CSS flip with no roving tabindex and no active item. |
| [CAN-B3-016](#can-b3-016) | The toolbar's exposed pressed state | CKEditor binds command.value to aria-pressed (and aria-checked on menuitemcheckbox), the only place command.value reaches AT. Lexical renders the identical bitfield as a CSS class only, on ~14 format buttons — though FindReplace and Review in the same codebase do use aria-pressed, so it is an omission, not a house style. Open Notebook has no active concept at all. |

The sharpest cluster is the **Enter contract**: within Lexical alone, a blockquote exits on any
Enter, a code block needs two blank lines, a top-level list needs one empty item, and a nested
list item drops a level instead of leaving — four rules, one editor, one keystroke, none of them
announced and none of them discoverable. See CAN-CB-008, CAN-CB-009, CAN-CB-026, CAN-CB-044,
CAN-CB-046, CAN-CB-047 and CAN-CB-069.

## The canonical set

Grouped by bucket, then by priority. Within a group, CB rows keep container order (blockquote,
code block, list, task list, table, nested editables, collapsible, columns, restricted, absent,
cross-cutting) so a container's vectors stay together — that grouping is what
[conformance-suite-design.md](../contract/invariants.md) instantiates its invariants over.

## CB — Container boundary crossings

The highest-volume class and the one with the sharpest evidence. does it silently, the other two do not do it at all), `CAN-CB-081` (collapsible — Lexical ships
a broken one, CKEditor ships none) and `CAN-B2-002` (the pending-style case does not arise in
Open Notebook at all). In each, `n/a` is the honest score and `silent` would have been a lie in
the editor's favour or against it.

---

## What this set is for

1. **It is the publishable comparison** — the artefact step 1 of
   [synthesis.md](../docs/synthesis.md#what-to-do-next) asks for.
2. **It is the scenario data layer** of
   [conformance-suite-design.md](../contract/invariants.md): the CB rows are already
   `container × vector` tuples, so the eight containment invariants can be instantiated over
   them directly, and `needsToKnow` is the first draft of the suite's semantic-token
   vocabulary — `{ conveys: ['direction:entered', 'container:blockquote'] }` rather than a
   regex per clause.
3. **It is the gap register.** Every row whose `gapType` is `standards` is, by construction, a
   place where a conforming implementation must still synthesise an English sentence — which is
   the definition of a hole in ARIA that [layered-gap-analysis.md](../docs/the-gap.md)
   sets out to enumerate.
4. **It is the contract our own editor is measured against.** Open Notebook has the worst result
   of the three and an announcer nothing calls; fixing it against a written contract rather than
   ad hoc is both better work and a better story.
